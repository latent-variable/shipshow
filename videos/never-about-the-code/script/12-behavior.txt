You don't need to understand each line. You need to understand the behavior. What must it never do? Show one customer another customer's invoice, say. So you write that test. It fails until the agent gets it right, and it fails again if anything ever breaks it. Karpathy's advice is the same. Give it success criteria, and watch it go. But a test only checks what you thought to ask. So when something surprises you, drop down a rung and read the code.
